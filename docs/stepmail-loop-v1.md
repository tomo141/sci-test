> 旧仕様の履歴。2026-09-14の改装ではこの毎日7通・腕試し10問の案を採用していない。現行の実装・未接続箇所は [MAIL-DELIVERY.md](../implementation/MAIL-DELIVERY.md) を参照する。以下をそのまま配信原稿や実行指示にしない。

## 方針

- 「最初の300人向け7日間キャンペーン」は**別立てで作らない**。
- エバーグリーンなステップメール（登録日を起点に自動配信）を1本作り、300人は**その最初のコホート**として流す。
- 例外として、ローンチ告知の単発ブロードキャスト（Day 0）だけは300人向けに1通送る。「最初の300人」という特別感はこの1通に込める。
- 7日間の目的は販売ではなく**アクティベーション**（初回受験 → カルテ閲覧 → 再受験・トレーニング習慣化）と、返信・アンケートによる**定性データ収集**。
- 原則：1通 = 1メッセージ = 1CTA。リンクには必ずUTMパラメータを付ける（例 `?utm_source=email&utm_campaign=onboarding&utm_content=day1`）。

差出人名は「理系とーく（全分野科学検定）」で統一。`{ニックネーム}` は差し込み変数。

## Day 8以降（無限ループ部分の設計）

頻度は週2通（例：火・金）。以下のフォーマットをローテーションで無限に続ける。

| フォーマット | 内容 | 主目的 |
|---|---|---|
| 今日の1問 | 問題バンクから1問＋解説誘導 | 開封習慣・トレーニング流入 |
| 分野特集 | 1分野の面白テーマ＋その分野のトレーニング誘導 | 苦手分野の受験 |
| ランキング・カルテ便り | 「今週の傾向」「上位の動き」 | 再受験 |
| 新着・改善のお知らせ | 新問題追加、機能改善（βの改善速度を見せる） | 信頼・再訪 |
| ストーリー・コミュニティ | 理系とーくの話、ユーザーの声紹介 | 関係構築・返信 |

- キューは「登録日起点の順番配信」にする（全員が同じ順番で受け取る）。
  こうすると全メールが常に新規読者にも届き、改善が資産として蓄積する。
- キューの末尾に到達した読者には、その時点の新作から時系列で配信を継続。

## PDCA運用

### 計測する指標（メール×アプリ行動）

| 指標 | 取得元 | 目安（下回ったら改善） |
|---|---|---|
| 開封率 | 配信ツール | 30%（ただし後述の注意あり） |
| クリック率（CTR） | 配信ツール | 3% |
| 配信停止率 | 配信ツール | 1通あたり0.5% |
| メール経由の受験開始 | UTM＋event_logs | Day1メールで20% |
| 7日以内の初回受験率 | event_logs | コホートの50% |
| アンケート回答率（Day 7） | 計測リンク | 15% |

注意：開封率はApple Mailのプライバシー保護で水増しされるため、
**主指標はクリックとアプリ内行動（UTM経由の受験・トレーニング）**にする。

### 300人規模での回し方

- **A/Bテストはまだやらない。** 150 vs 150 では、開封率で20ポイント級の差がないと統計的に検出できない。
- 代わりに**逐次改善**で回す：全員に同じ版を送り、前号・前週コホートと比較する。
- この規模で一番価値があるのは数値より**返信・アンケートの生の声**。Day 6・Day 7の返信導線を大事にする。
- リストが1,000人を超えたら件名A/B（50/50、開封で判定）から開始する。

### 週次サイクル

1. **月曜：Check** — 前週配信分の開封・CTR・UTM経由行動をスプレッドシートに記録（1通1行）
2. **同日：Act** — 最下位1通だけを特定し、仮説を1つ立てる（件名か、CTAか、送信時刻か——**変えるのは1要素だけ**）
3. **火曜〜：Do** — 書き換えた版を配信キューに反映。以降の新規登録コホートに適用
4. **翌週以降：Check** — 新旧コホートで同じ通番の数値を比較。改善していれば確定、悪化なら戻す

### 月次サイクル

- シーケンス全体を見て、Day 1→7 のどこで脱落（未開封が連続し始める地点）が起きるか確認し、並び順・間隔を見直す
- 「7日以内初回受験率」をコホート月別に比較（これがオンボーディングの成績表）
- ループ部分（Day 8以降）は、成績下位のフォーマットを新フォーマットと入れ替える
