# セルフレビュー・チェックリスト

作成した問題を出力する前に、**全問**に対して以下を実行する。
1つでも FAIL があれば修正し、修正後に再チェックする。
大規模検定の実務では独立した複数人(内容レビュー・編集レビュー・バイアスレビュー)が
行う工程であり、それを1セッション内で模擬する。

## フェーズ1: 独立解答テスト(最重要)

- [ ] 正答キーを見ずに、受験者になったつもりで問題を解いた
- [ ] 自分の答えがキーと一致した
- [ ] 「別の肢も正解と言えるのでは?」と意図的に反論を試み、すべて退けられた
- [ ] 幹の条件だけで答えが一意に定まる(暗黙の前提に頼っていない)

**一致しなかった/反論を退けられなかった場合は必ず修正。**
このテストをすり抜けた複数正答問題は、運用後に検定の信頼を最も大きく損なう。

## フェーズ2: 手がかり漏れ検査(内容知識ゼロで解けないか)

「この分野を全く知らない人」の視点で選択肢だけを眺めて:

- [ ] 1つだけ長い・詳しい・限定条件付きの肢がない(正答は往々にして長くなりがち)
- [ ] 幹の語句が特定の肢にだけ反復されていない(clang association)
- [ ] 幹と文法的に自然に接続するのが正答だけ、になっていない(冠詞・活用・単複)
- [ ] 「常に」「決して」「すべて」等の絶対語が誤答肢の目印になっていない
- [ ] 対になる2肢(正反対の主張)で正答が絞れる構造になっていない
- [ ] 他の問題の幹・選択肢が、この問題のヒントになっていない(セット内の相互干渉)

## フェーズ3: ルール準拠チェック

- [ ] 1問1論点になっている
- [ ] 幹だけで問いが完結する(選択肢を隠しても何を問われているか分かる)
- [ ] 否定形の幹を使っていない(使う場合は強調済みで、正当な理由がある)
- [ ] 「上記すべて」「該当なし」を使っていない
- [ ] 選択肢が相互排他的
- [ ] 選択肢の長さ・文法・スタイルが揃っている
- [ ] 数値選択肢は昇順/降順
- [ ] 不要な背景情報(window dressing)がない

## フェーズ4: 誤答肢の設計検証

各誤答肢について:

- [ ] 「どの誤概念・典型ミスを捕まえる肢か」が1行で書けている
- [ ] その誤概念は、対象受験者層が実際に持ちそうなものである(作問者の空想でない)
- [ ] 明確に誤りである(部分的に正しい肢になっていない)
- [ ] 捨て肢(誰も選ばなそうな明白すぎるハズレ)になっていない

## フェーズ5: 難易度・公平性

- [ ] 目標難易度帯が割り当てられ、想定正答率が記録されている
- [ ] 難しさが認知的要求から来ている(引っかけ・瑣末な表記差で難しくしていない)
- [ ] 測定対象外の前提知識(特定文化・地域・職業でしか通じない知識)を要求していない
- [ ] 不快・動揺を招く題材を使っていない
- [ ] 素材文はオリジナルである(実在著作物の転載でない)

## フェーズ6: セット全体の検査(複数問のとき)

- [ ] 正答位置(A/B/C/D)がほぼ均等に分布している
- [ ] 難易度分布がブループリントの計画と一致している
- [ ] 領域・認知レベルの配分がブループリントと一致している
- [ ] 問題間で内容の重複・相互ヒントがない
- [ ] メタデータ(ID・領域・認知レベル・難易度帯・誤答肢根拠・解説)が全問に付いている

## レビュー結果の報告

ユーザーへの出力時、末尾に簡潔なレビューサマリを添える:
「全N問にセルフレビューを実施。独立解答テスト一致 N/N、修正した問題: #3(選択肢の長さの偏り)…」
のように、何を検査しどこを直したかを透明化する。これが品質の証跡になる。
