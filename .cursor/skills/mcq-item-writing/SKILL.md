# 選択肢式問題 作成スキル(MCQ Item Writing)

> **本リポジトリ**: 問題作成の入口は `science-question-creation`。レベル付けは
> `skills/science-question-level-calibrator` が正本。`references/difficulty-and-scale.md`
> の TOEIC 型帯は**本検定では使用しない**。

能力検定レベルの品質を持つ選択肢式問題を、体系的な手順で作るためのスキル。
原則は測定学(サイコメトリクス)の標準的知見 — Haladyna & Downing の作問ガイドライン、
Evidence-Centered Design、項目応答理論(IRT)— に基づく。

**中核思想:良問は「書く」ものではなく「設計する」もの。**
1問ごとの思いつきではなく、仕様 → 設計図 → 作成 → 検証の順で作ることで再現性が生まれる。

## 参照ファイル(必要時に読む)

- `references/item-writing-rules.md` — 作問ルール全集(幹・選択肢・誤答肢の詳細規則)。**問題を書く前に必ず読む。**
- `references/difficulty-and-scale.md` — 難易度設計と10〜990点型スケールへの対応。難易度帯の割り当てが必要なとき読む。
- `references/review-checklist.md` — セルフレビュー用チェックリスト。**作成した問題を出力する前に必ず読んで全問チェックする。**

## ワークフロー(必ずこの順で)

### Step 0: 仕様の確認

作問を始める前に、以下が揃っているか確認する。不明な点はユーザーに確認するが、
少数なら合理的なデフォルトを置いて明示的に宣言して進めてよい。

1. **構成概念(コンストラクト)**: この検定は何の能力を測るのか。1文で定義できること。
   (例:「ビジネス文脈における英語の聴解・読解力」)
2. **受験者像**: 想定される受験者の層と能力分布。
3. **測定領域**: 能力をどんな下位領域に分けるか(例:語彙/文法/読解/推論)。
4. **スコアスケール**: 素点か、10〜990点型のスケールドスコアか。後者なら
   `references/difficulty-and-scale.md` を読み、難易度帯(バンド)を定義する。
5. **形式仕様**: 選択肢数(推奨は3〜4肢)、問題数、素材(文章・図表)の有無。

### Step 1: ブループリント(出題設計表)の作成

複数問を作る場合、いきなり書き始めず、まず設計表を作ってユーザーに提示する。

| 領域 | 認知レベル | 難易度帯 | 問題数 |
|---|---|---|---|
| 例: 語彙 | 知識・再認 | 帯2 (300-500) | 4 |
| 例: 読解 | 適用・推論 | 帯4 (700-860) | 3 |

- **認知レベル**は最低2段階を区別する:「知識・再認」(覚えていれば解ける)と
  「適用・推論」(知識を新しい状況で使えないと解けない)。良い検定は後者を十分含む。
- **難易度分布**は受験者層の中心付近に厚く、両端にも配置する(識別したいスコア帯に問題を置く)。
- 1問だけの依頼でも、領域・認知レベル・目標難易度帯の3点は決めてから書く。

### Step 2: 問題の作成

`references/item-writing-rules.md` を読んでから書く。要点:

- **1問1論点**: 各問題はブループリント上の1つのセル(領域×認知レベル)だけを測る。
- **幹(設問文)完結主義**: 選択肢を読まなくても何を問われているか分かる幹を書く。
- **誤答肢は設計物**: 各誤答肢は「特定の誤概念・典型的ミスをした受験者が選ぶ肢」として作り、
  その設計根拠を必ずメタデータに記録する。「もっともらしいハズレ」を適当に並べない。
- **再現性のためのアイテムシェル**: 類題を量産する場合、うまくいった問題を
  「変数スロット付きテンプレート」に抽象化し、スロットの値を変えて展開する。

### Step 3: セルフレビュー(出力前に必須)

`references/review-checklist.md` を読み、全問に対して実行する。特に:

1. **独立解答テスト**: 正答キーを見ずに自分で問題を解き、キーと一致するか確認する。
   一致しない・複数の答えが成立する場合は修正必須。
2. **手がかり漏れ(clue)検査**: 文法的整合・長さ・言い回しの反復などから
   内容知識なしで正答を推測できないか。
3. **チェックリスト違反ゼロ**を確認してから出力する。

### Step 4: 構造化出力

各問題は必ず以下のメタデータ付き構造で出力する(問題バンク管理と後日の統計較正のため)。
ユーザーが形式を指定した場合はそれに従うが、メタデータは省略しない。

```
## 問題 [ID]
**領域**: … / **認知レベル**: … / **目標難易度帯**: 帯N(スコア目安 XXX–XXX)/ **想定正答率**: NN%

**問題文(幹)**:
…

A. …
B. …
C. …
D. …

**正答**: B
**解説**: なぜBが正しいか。
**誤答肢の設計根拠**:
- A: [この肢が捕まえる誤概念・典型ミス]
- C: [同上]
- D: [同上]
```

大量出力時はJSONやスプレッドシートも可(同じフィールドを保持すること)。

## 絶対規則(違反したら出力しない)

1. 正答は1つだけ。専門家が見て議論の余地なく1つに定まること。
2. 誤答肢はすべて「明確に誤り」かつ「その誤概念を持つ人には魅力的」であること。
3. 「上記すべて」「該当なし」は使わない。
4. 幹の否定形(〜でないものは?)は原則使わない。やむを得ず使う場合は**太字**で強調。
5. 引っかけ(トリック)で難しくしない。難しさは内容の認知的要求から来るべき。
6. 特定の属性(性別・地域・文化・年齢)に不利な前提知識・題材を混ぜない。
7. 正答の位置(A/B/C/D)はセット全体で均等に分布させる。
8. 実在の著作物からの本文転載はしない。素材文は必ずオリジナルで作る。
