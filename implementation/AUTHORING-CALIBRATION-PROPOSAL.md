# 作問基準・分野別アンケート・実測難易度をつなぐ案

記録日: 2026-09-16 JST。本人の追加要望に基づく**未採択の提案**。採点式、既存問題の難度、本番のアンケートや作問フォームは変更していない。

追記: 本人が同日「アンケート少しずつってのはいい」と段階的な質問を支持し、「◯◯の人が70%正解できる問題を、自分も70%ほど答えられそう」の最も近い段階をラジオボタンで選ぶ案を提示した。作業完了後に必要な判断をおすすめ付きで確認する依頼も受けた。以下のラジオボタン案は画面文案として具体化し、採点や集団定義への採用を確定したものとはしない。

## 追加の自己評価ラジオボタン案

本人の案は学歴・履修経験の申告から、現在の知識についての自己評価へ重点を移す。独学の人や専門を離れた人も答えやすくなる。一方、実際の「◯◯の人」の母集団を識別する情報は別に必要。

画面案は、共通の説明を一度だけ示し、ラジオボタンには対象者の段階を短く書く。

> 有機化学で、今の自分に一番近い段階は？
>
> 各段階の人が10問中7問ほど正解する難しさの問題を、自分も10問中7問ほど解けそうな段階を選んでください。学歴に関係なく、現在の感覚で選べます。
>
> ○ 高校の有機化学を学んだ人向け
> ○ 大学の入門科目を学んだ人向け
> ○ 大学の専門科目を学んだ人向け
> ○ 大学院の専門科目を学んだ人向け
> ○ まだ判断できない／後で答える

各段階に代表問題を任意で開ける入口を付ける。二重の70%が分かりにくい場合の短い主文案は「10問中7問くらい解けそうな段階は？」。対象者側の70%の定義は補足に置き、数値の意味を省略して別の定義にすり替えない。

保存は `self_assessed_level`、対象小分野、質問文・基準の版、回答日時。履修・研究経験は `learning_experience` として別の時点で任意に聞く。自己評価を選んだだけの人を、実際の学位取得者や専門科目履修者の母集団に入れない。自己評価の当たり具合自体も実績から検証する。本人の点数をこの回答で直接補正しない。

運営者が最後に決める候補: このラジオボタンを主質問、履修・研究経験を後日の補助質問にする案を推奨。二重の70%を本文で毎回繰り返す表示と、補足へ分ける表示は少人数で理解度を比較する。

## 本人の要望と推奨案

本人は、いろいろな人に作問してもらうため、基準の正答率を作問者がイメージしやすいことを重視している。「その分野をどこまで学んだ人か」を回答者から分野ごとに取得し、実績による難易度補正へつなげたい。

初期案は「その分野を、指定した段階まで学んだ人10人を想像したとき、初見・検索やAIなしで、7人くらいが四択の正解を選べる問題」。70%が万人にとって最も想像しやすいと実証されたという意味ではない。人数で説明しやすく、学習済みの人の多数が解ける内容として考えやすい、という本製品向けの提案。

| 候補 | 作問時の見方 | 留意点 |
|---|---|---|
| 50% | 10人中5人。解ける・解けないの境目 | 境目は説明しやすいが、その段階の人が身に付けた標準的な知識として想像しやすいかは別に検証する |
| 60% | 10人中6人。半分よりやや多い | 十分使える候補。70%との想像しやすさの差は未検証 |
| **70%** | **10人中7人。多くの人が解け、一定数は迷う** | **初期推奨。専門家の思い込みを抑える代表例と実測フィードバックを添える** |
| 80% | 10人中8人。広く定着した基本知識 | 基本事項の確認には使える。同じ対象集団なら70%基準より容易な問題になる傾向 |

この率は、推測による正解も含む実際の四択の正答率。知っていて説明できる人の割合とは一致しない。「10人」は作問時のイメージであり、10人の実測だけで難易度を確定する条件ではない。68.3%の情報量最大化とも別の設計判断。

ETSの基準設定マニュアルは、確率を見積もりにくい判定者に対し、想定する受験者100人のうち何人が正解するかを考える補助法を示す。この提案の10人・70%はその数値をそのまま採用したものではなく、本サービス向けの簡略化である。[ETS, Passing Scores, Angoff’s Method](https://www.ets.org/Media/Research/pdf/passing_scores.pdf)

## 作問者に見せるもの

数値レベルを直接当ててもらう負担を減らす。投稿画面では以下を見せる。

1. 問題の小分野を選ぶ。例: 化学 → 有機化学。
2. 「どの段階まで学んだ人なら、10人中7人くらいが解けそうか」を選ぶ。
3. 対象者の短い説明と、同じ対象者向けの代表問題3問程度を見る。公開前は専門家による仮例、実測後は出典と版を明示した実例とする。
4. 見積もりへの自信を「ある／迷う／判断できない」から選ぶ。判断できなくても投稿でき、審査で補う。
5. 複数の審査者が、他者の判定を見る前に対象段階を選ぶ。意見が大きく割れる問題を先に確認する。

「その人は知っているべき」ではなく、「実際に初めて解いたら、どの程度正解しそうか」を考えてもらう。知られていない固有名詞や、論文の細部だけで難度を上げる誘導はしない。難しくても良問は受け付け、より高い段階やラボの問題として扱える。

作問者が学部向けを選んだのに実測で高校段階でも解けた場合、問題の不備がなければ難度を補正する。基準の70%に無理やり合わせるために問題本文を改変しない。本文や選択肢を変更した場合は別の問題版として較正する。

## 共通の「対象者カード」

作問画面と回答者アンケートは、共通の小分野ID・学習経験コード・定義版を使う。自由記述の「専門家」だけでは集計しない。

対象者カードの例:

> 有機化学を大学の専門科目として、所定の基礎範囲まで学んだ人。典型的な反応、構造、基本的な立体化学を扱った経験がある。化学の他分野だけを専門にした人や、入門科目を一つだけ履修した人は同じカードにまとめない。

カードには、想定する学習範囲、履修・修了条件、対象の小分野、代表問題、最近の利用状況の扱いを明示する。「標準的」「優秀な」「上位」だけで対象者を定義しない。

初期の共通経験コードの候補:

| 経験 | 入力例・注意 |
|---|---|
| 未学習／判断できない／回答しない | 三つを区別する。未回答を未学習と扱わない |
| 学校の基礎範囲まで | 小・中・高校のうち、その小分野に対応する履修範囲を分野別に示す |
| 大学の入門・教養科目まで | 専門課程とは分ける |
| 大学の専門科目を体系的に学習 | 単に学位を持つかではなく、該当分野の学習範囲を確認する |
| 大学院の専門科目を学習 | 修士・博士の在籍や取得は補助情報として分けられる |
| 該当小分野で研究・専門実務を経験 | 学位より必ず高い能力という順序にはしない。研究・実務と授業履修は併存可能 |
| 独学・その他の経路 | 対応する学習範囲を選べるようにする。独学という経路だけで低い段階にしない |

実装上は、学習範囲、経路（学校・独学等）、研究・実務経験を分ける。画面では短い選択肢へまとめ、細部は必要なときだけ聞く。

最近の利用状況は別項目とする。案: 「現在も使う・学ぶ／最後に使ったのは1年以内／1〜5年前／5年以上前／不明」。境界年数も未採択。学習経験と忘却・現役利用を一つの序列に混ぜない。

最初の基準カードは、最近使っている人の条件を明示したものから整備する案を推す。卒業後に長く離れている回答も捨てず、別層として持つ。全卒業者の代表正答率を主張するには、卒業後年数などの構成比を別に定めた標本が必要。

旧表の「共通テスト上位」「旧帝大院試受験者」などは履修段階と選抜集団が混在している。旧50刻みを新経験コードへ自動対応させない。特に250・350等を曖昧な「上位」で埋めず、分野別の学習範囲で基準カードを作り、実測難度の表示を50刻みに丸める方針を検討する。

## 回答者への聞き方

最初の腕試しやメール登録の前に、10大分野・100小分野のアンケートを一度に課さない。メール登録数を最優先にする既定方針を保つ。

1. 結果画面で、得意・学習経験のある大分野を任意で選べるようにする。
2. その分野の受験後、関連する小分野について共通カードの短い質問を出す。プロフィールからもまとめて編集できる。
3. 一度回答した情報は再利用し、本人の変更と履歴を残す。回答イベントには、その時点の自己申告と定義版を結び付ける。
4. 他分野の学位から、すべての小分野の経験を自動入力しない。スキップ可能、非公開を初期値とする。

アンケートは問題の検証と対象集団の推定に用いる。回答の有無や学歴で本人の今回の得点を上げ下げしない。本試験の出題を過去の実力で変えない、という採択済み方針にも流用しない。

## 実績から補正する流れ

保存する値は、初期見積もりと実測を分ける。

- 初期: 作問者が想定した対象者カード、目標70%、見積もりの自信、初期難度、問題版。
- 回答: 問題版、選択肢、正誤、分野別経験の当時の記録、直接・同系統の既出情報、出題方法と選択確率、採点・問題パラメーターの版。
- 実測: 較正したa・b・cと不確かさ、対象者別の正答率・推定幅、初見の独立回答者数、能力帯の広がり、モデル・基準集団の版。

処理は次の順で行う。

1. 初期難度を弱い事前情報として出す。自信が低い見積もりは不確かさを大きくする。
2. 安定した共通問題で能力尺度を保ち、対象者の異なる能力帯から初見の回答を集める。適応出題だけの実績正答率を、そのまま問題難度にしない。
3. 初期はa・cを共通値に固定し、各回答者の能力の不確かさを含めてbを推定する。十分なデータと別データへの予測改善を確認した後にa、最後にcを検討する既定方針を継承する。
4. 対象者カードごとの予測正答率も計算し、想定70%とのずれを検証する。ずれが大きければ、難度・カードの範囲・選択肢の不備・特定集団だけの有利不利を切り分ける。
5. 自動更新は運営用の候補値まで行う。推定幅、能力帯の偏り、保留データでの予測、尺度の安定性が基準を満たしたものを版単位で採用する。開始済み受験と過去の受験記録の尺度を無記録に書き換えない。

運営の検証用出題枠の一部で、各対象層に初見問題をランダムに割り当てる。既定の重点群の入替と併用する。適応出題で強い人へ難問を多く出した結果、どの問題も正答率が似たからといって同難度にはしない。独立した検証用の回答を持ち、出題ログを保存する。

再出題は本人の今回のスコアに含める、という明示決定を維持する。難度の較正では既出回答を除外し、同じ概念の解説を直前に読んだ影響も検討する。悪問報告だけで正解や本文を自動変更せず、出典と審査を通す。

自己申告した人は、全学位取得者等の無作為標本ではない。実測表示はまず「本サービスの該当回答者における初見正答率」とする。既知の構成比がない集団を補正して、全国の博士の代表値と称することはできない。[NCESの標本・重み付けとIRTによる推定](https://nces.ed.gov/statprog/handbook/naep_surveydesign.asp)

## 問題難度・個人スコアへの数理的な接続

70%を採用するなら、個人の分野能力と問題の実測難度も70%対応に揃える案を推す。これは先の50%表示案からの変更候補であり、未採択。

`p_i(θ)=c_i+(1-c_i)σ(a_i(θ-b_i))` とすると、任意の基準率r（c_i < r < 1）を満たす能力は

`θ_i,r = b_i + (1/a_i) ln((r-c_i)/(1-r))`。

能力を共通表示点へ変換する単調関数をSとすれば、問題の実測難度を `D_i,r=S(θ_i,r)`、個人の分野実力を `S(θ)` とする。このとき同じ数値なら、その個人のその項目へのモデル上の正答確率はrになる。表示を50刻みに丸めた値では近似になる。

r=.70、c=.25なら `θ_i,70=b_i+ln(1.5)/a_i`。3PLのbと個人θを単に同じ値にする場合の62.5%とは異なる。rを変える場合は換算と版をセットで管理する。

一方、対象者カードGの平均正答率は

`p̄_i,G = ∫p_i(θ) f_G(θ)dθ`。

同じ履修経験でも能力は分布するので、Gの平均70%と、平均能力の個人の70%は一般に一致しない。プロフィールを使って各層の能力分布を共通問題の実績から推定し、この式で集団側の見積もりを検証する。

一貫性は、共通の対象者定義・問題版・能力尺度を通じて実測へ接続することで保つ。ある学位を持つ人の点を一律に固定することで作らない。初期の学習段階は見積もり、D_i,70は較正結果として、ずれを観測可能にする。

総合点は10大分野の無加重合計を維持する。総合500から、各分野の難度500へ一律70%正答すると解釈することはできない。分野の偏りを科学マップで示す。

現行実装の固定参照スコアは、この70%対応も先の50%対応も保証していない。990への到達性、短い受験での中央への偏りと併せて、採点式を改めて比較・検証する必要がある。[既存定義と現行実装の監査](DIFFICULTY-AND-SCORE-REVIEW.md)

## 少人数で確かめること

70%の採択後も、作問者の判断支援を改善する実験ができる。最初の小規模検証では、同程度の経験のある作問者へ、同じ分野の異なる代表問題セットを順序を変えて割り当てる。

- 60%と70%で、基準対象者の選択にかかる時間、自信、独立した作問者間の一致、後の実測とのずれを比較する。必要なら50%を加える。
- 「70%」だけの表示と「10人中7人＋対象者カード＋代表例」を比較する。
- 単なる判定一致だけでなく、保留しておいた実際の回答をどれだけ予測できるかを見る。全員が同じ思い込みを持つ場合は、一致しても正確ではない。
- 少人数の予備調査を万能な最適率の証明とは扱わない。回答者の募集難度、フォームの離脱、公開後の測定精度も併せて確認する。

百分率を変更すると同じ問題の尺度上の位置が変わるため、本番の意味付けは受験者ごとに無作為変更しない。実験はまず作問支援の段階で行い、採用する尺度は版ごとに統一する。
