# 改装の実装境界

2026-09-14。既存Next.js/Supabaseを継続し、旧テーブルを削除せず新版の受験を追加する。

- 旧版のアカウント・成績・利用権・配信解除を保持する。旧スコアは新尺度に換算しない。
- 受験定義・出題・回答・結果の所有確認はサーバー。ブラウザからDBの成績・正解・権利・管理役割へ直接書き込めない。
- 256bitの匿名秘密をHttpOnly Cookieに置き、DBではハッシュで照合。ログイン後の統合にも同じ証明を用いる。
- 統合時には、別端末の先行閲覧と旧版の問題族対応を再照合する。既出と判明した回答は別の除外記録で実力推定から外し、元の回答・出題・結果版は保持する。対象の受験は参考参加とし、再集計前は順位対象から外す。新しい旧ID対応をインポートした場合も、検証済み会員へ再照合を実行する。
- 問題版と公開バンク版を不変にし、受験開始時の版を固定。休止・権利疑義の問題は新規提示を止める。
- 回答確定はDB行ロックと操作IDを使うRPCで、提示・正誤・進捗・完了成績・確定イベントを一括保存する。失敗時に成功を返さない。
- 採点は10大分野を独立に推定し、分野0〜100点を無加重合計。初期3PLはa=1,c=.25を仮定し、固定参照難度-2,-1,0,1,2から点へ換算する。校正・尺度の外部検証前は参考スコアと表示。
- 現在の推定は各分野の適格な直近100回答、回答順の半減期30件。生回答を消さず、今回・現在・自己ベストを分ける。
- 小分野受験の解放時には、本人が9/15に提案した[6軸レーダーと「全分野科学力」](FUTURE-SUBDOMAIN-SCIENCE-POWER.md)を再検討する。総合・大分野上位3・小分野上位2の平均を5刻みに丸める将来案で、尺度の統一などは未決。現行の採点へは未実装。
- 出題は必要分野配分を制約に、事後分布上の分野点の期待分散減少を評価。上位候補、重点群、全適格候補の既知の確率混合で選ぶ。未見条件を緩めて水増ししない。
- 初回候補の重点群は各大分野20問を、小分野の配分と仮難度の広がりから決定的に選ぶ。週替わり専用・アンカーを除き、指定した少数の重点問題は保持する。20は運用の初期値で、効果を実測した最適値ではない。問題内容・正解の版と重点配分の版を分離する。初期のアンカーは0問で、安定性未確認の問題を校正済みアンカーにしない。
- 難度校正は最大20問／実行。200人以上を入口とし、前回評価から追加50人までは同じ検証を繰り返さない。問題訂正後は再検証し、公開を有効にした際も保存済み合格をそのまま適用せず現在の回答で計算し直す。分野ごとに処理枠を回し、別の公開版へ進んでも前回評価の記録を引き継ぐ。適用時は訂正の版・元のb・重点指定・a/c固定・問題ごとの一意性をDBで再確認する。
- 固定4導線の実験版を先行。長さは50問固定、100問は設定で比較できる構造。登録で受験権を付与し、メール配信は別の任意同意として既存規約との一貫性を保つ。
- 週替わりはJST月曜00:00で10問を固定。ランキングは初回完了・同点同順位・速度不使用。公開は明示選択。正式スコア比較の妥当性未検証は表示に残す。
- 投稿の著作権は作者に残す。利用許諾の未確定細目や法務確認を、実装が済んだだけで確定扱いしない。
- 運営指標は実際に取得したデータと対象期間を表示。0・未接続・エラーを区別し、静的な架空実績・無断フォールバックを使わない。

SQLのテストはPGliteのPostgreSQLで行う。Supabase Auth・HTTP/RLS・複数接続の競合・本番メール受信の検証とは区別する。
