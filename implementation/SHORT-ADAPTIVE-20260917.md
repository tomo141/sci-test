# 短問100問と、回答に応じた腕試し

観測・記録日: 2026-09-17 JST。出典はこのタスクでの本人の採択・補足と、下記のローカル検証。科学検定の作業記録であり、kinako3の事業全体の正本は変更しない。

## 本人が決めたこと

- 最初の20問の文量・テンポを維持する。最初の固定20問は体験済み。
- 残り80問をすべて難しくするのではなく、レベル1〜7をまんべんなく作る。
- 問題には最初から仮レベル・仮難度を設定し、回答の正誤に応じて出題する難度を上げ下げする。
- 腕試しは予測正答率75〜85%の短問を優先し、その範囲で実力を見分ける。本試験は測定精度を優先する。
- 難度と実力の70%対応、総合10〜990点、分野1〜99点は維持する。過去回答は腕試しの選定にだけ今回と同じ重みで使い、今回のスコアに混ぜない。

最初の「少し難しくする」を、80問すべての作問難度を上げる指示とは扱わない。後の本人の補足を優先した。公開スコア帯と人物像の対応を新しく決めたものではない。

## 作成・実装したもの

[原稿100問](../content/science-short-balanced-20260917.json)、[全問の正解・解説・出典・旧問題との対応](short-questions/balanced/REVIEW.md)、[自動点検](short-questions/balanced/audit.json)。10分野各10問。各分野にレベル1〜7を最低1問ずつ配置し、全体は15・15・14・14・14・14・14問。問題文は平均23.8文字・最大41文字、選択肢は平均4.6文字・最大14文字。断定語などの編集注意点は自動監査で0件だったが、科学的正確さを自動検査だけで保証する意味ではない。

仮難度は各レベル内の100・225・375・525・675・825・925を初期値とした。これは作問者による見立てで、実回答による校正済み難度ではない。既に本人が採択した150・300・450・600・750・900のレベル境界を使用する。

採択済みの換算は、実力座標を `S = 500 + 200θ`、`a = 1`、`c = 0.25` とし、仮難度Dについて `b = (D - 500) / 200 - log(1.5) / a`。これにより実力SとDが同じときの予測正答率は70%。選定は表示レベルの大小だけでなく、bと回答から求めた分野別の事後分布を使う。本文を変えた問題へ旧b・旧回答実績をそのまま移植していない。

[適応20問の試用](short-questions/adaptive.html)は、100問から各分野2問ずつを選ぶ。新規の腕試し用に実装した本番コードの選定・採点・途中表示の関数を直接使用し、別の採点式を作っていない。最初の1問から未測定分野の仮推定を含む総合点と推定幅を表示する。端末内に保存されている最初の20問も、展開欄で仮難度による参考スコアへ計算できる。

試用では前回の回答を出題に使う設定を初期オンにした。回答と履歴は端末内にのみ保存し、正式受験・ランキング・校正データには入れない。最初の固定20問の画面・保存内容は変更していない。科学用語の表記、クリック即回答、数字キーの選択／即回答切替、正誤と解説、中断再開を提供する。

本番アプリ側では新規の腕試しを `exam-v4-trial-fluency` / `trial-fluency-v1` に版分けした。中断受験・本試験の出題と採点は保持する。候補選定で新しく取得するのは文量判定のための問題文・選択肢で、候補全問の正解・解説・出典は取得しない。

## 回答による難度の動きと限界

各分野の正誤からその分野の実力推定を更新する。数学で正解しただけで、未回答の生物を難しくする実装ではない。分野枠・未見優先・予測正答率を同時に守るため、正解の直後に次の表示レベルが必ず1上がるという階段方式でもない。

履歴のない架空受験者の[動作検証](checks/short-adaptive-simulation-20260917.json)では、全問正解時は各分野の1問目がレベル2、2問目がレベル3。不正解が続く場合は2問目がレベル1になった。正解履歴が増えると選定難度が上がることも単体検査した。これは人工的な回答による動作確認で、本人のスコアや実測の正答率ではない。

20問では各分野2問のため、初回だけで高得点者を細かく見分ける精度には限界がある。推定幅を表示し、50・100問や複数回の実回答を用いた精度評価につなぐ。仮難度の誤差と測定精度は別に検証する。

## 検証結果

- 単体・DB検査246件成功。任意の実バンク検査1件は通常実行で除外し、別実行で既存1,000問を使った72回の仮想受験を確認した。
- 問題準備・編集監査の8件成功。全体Lint・型検査・本番用ビルド成功。
- 本番アプリのPC・スマホ試験44件成功、接続DBを要する2件は未実行。画面描画直後の数字キーを取りこぼす事象を再現し、ハンドラーを描画前に更新して回帰検査を追加した。
- 最初の固定20問と適応20問を、それぞれPC・スマホで20問完走。[適応試用の記録](checks/short-adaptive-browser-20260917.json)では分野配分、重複なし、途中スコア、過去履歴を今回の採点へ入れないこと、キー操作、再読込、横あふれなし、外部通信なしを確認した。
- 再訪計測はURL・メール・回答本文を送らず、既存受験者の表示中の訪問を1時間単位で重複除去する。7日間観測した初回受験者だけで比較する[読み取り専用SQL](operations/observe-trial-fluency.sql)をPGliteの架空データで確認した。前後比較を因果的な勝者判定とはしない。
